# GitHub PRのタイトルと本文を書くときのテンプレート

## 概要

GitHubのPull Requestを作成するときに使用する、タイトルと本文の基本テンプレートをまとめる。

タイトルの接頭辞は英語、説明部分と本文は日本語で統一する。

## PRタイトルの形式

```text
<英語の接頭辞>: <日本語の説明>
```

例：

```text
feat: ノート検索機能を追加
fix: コードブロックの余白を修正
docs: Cloudflareの設定手順を追記
refactor: ノート取得処理を整理
test: ノート作成処理のテストを追加
chore: 開発用パッケージを更新
```

## 接頭辞の使い分け

| 接頭辞 | 用途 |
| --- | --- |
| `feat` | 新しい機能の追加 |
| `fix` | 不具合の修正 |
| `docs` | ドキュメントのみの変更 |
| `style` | 動作に影響しない見た目や整形 |
| `refactor` | 機能を変えないコード整理 |
| `test` | テストの追加や修正 |
| `chore` | 設定、依存関係、開発環境の変更 |
| `perf` | パフォーマンス改善 |
| `ci` | CIやGitHub Actionsの変更 |

## PR本文のテンプレート

```markdown
## 概要

このPRで行った変更を簡潔に説明します。

## 変更内容

- 変更した内容
- 追加した機能
- 修正した問題

## 目的

この変更が必要になった理由を説明します。

## 影響範囲

- 利用者への影響
- 開発者への影響
- データベースや環境設定への影響

## 確認内容

- `npm run build`
- `npx eslint .`
- 対象画面の動作確認

## 補足

レビュー時の注意点や、マージ後に必要な作業を記載します。
```

## 書き方のポイント

- タイトルだけで変更内容が分かるようにする
- 1つのPRに関係のない変更を混ぜない
- 何を変更したかだけでなく、なぜ変更したかも書く
- 不具合修正では原因を記載する
- 実行した確認コマンドと手動確認を記載する
- データベースや環境設定への影響を明記する
- レビュー本文とコメントは日本語で記載する
- 機密情報、メールアドレス、APIキー、トークンは記載しない

## マージ前の確認

- PRタイトルが変更内容と一致している
- 英語の接頭辞が適切に使われている
- PR本文が空になっていない
- 不要なファイルが含まれていない
- 機密情報が含まれていない
- ビルドとLintが成功している
- 必要な動作確認が完了している
