# Helmorとは？複数のAIコーディングエージェントを管理する開発環境

## Helmorとは

[Helmor](https://helmor.ai/)は、複数のAIコーディングエージェントを一つの画面から管理する、オープンソースの開発環境。

Claude Code、Codex、Cursor、OpenCode、Kimi Codeなどに対応している。タスクごとにGit worktreeとブランチを用意し、エージェントの会話、コードの差分、ターミナルをまとめて確認できる。

コードを書かせるだけでなく、レビュー、テスト、Pull Requestの作成、マージといった、実装後の工程まで扱える点が特徴。CLIやMCPサーバーからHelmorを操作することもできる。

Helmor自体が新しいAIモデルを提供するわけではない。普段利用しているAIコーディングエージェントとGitの作業環境をまとめ、タスクの開始からコードを取り込むまでを管理するためのツールになっている。

## Helmorの主な特徴

### タスクごとに作業環境を分離する

Helmorでは、タスクごとにGit worktreeとブランチを作成する。

複数のエージェントを同じ作業ディレクトリで動かすと、変更中のファイルを別のエージェントが書き換える可能性がある。worktreeで作業場所を分けることで、それぞれのエージェントを独立した環境で動かせる。

作業内容はローカルの`~/helmor/`以下に保存される。ローカルファーストで利用できるため、普段使っているリポジトリとエージェントを、そのままHelmorから扱える。

### 複数のエージェントに対応している

Claude Code、Codex、Cursor、OpenCode、Kimi Codeなどに対応している。

タスクの内容によってエージェントを使い分けたり、複数のタスクを別々のエージェントへ依頼したりできる。各サービスのログインやAPIキーは、利用するエージェントに応じて必要になる。

### 差分確認からPull Request作成まで行える

エージェントとの会話だけでなく、変更されたコードの差分、エディタ、ターミナルを同じ画面で確認できる。

実装後はテストを行い、GitHubまたはGitLabでPull RequestやMerge Requestを作成できる。CIの修正や競合の解消などもHelmorからエージェントへ依頼できるため、コード生成後の作業も一つの流れとして管理しやすい。

### CLIとMCPから操作できる

デスクトップアプリに加えて、`helmor` CLIも用意されている。CLIでは、リポジトリの登録、workspaceの作成、エージェントへの指示、状態の確認などを行える。

また、MCPサーバーとして起動し、別のエージェントからHelmorを操作することもできる。人が画面から管理するだけでなく、エージェントによるタスク管理の自動化にも利用できそうだ。

## 基本的な利用の流れ

Helmorを使った作業は、おおむね次のように進む。

1. ローカルのGitリポジトリをHelmorへ登録する
2. タスク用のworkspaceを作成する
3. 利用するAIコーディングエージェントを選ぶ
4. エージェントへ実装や調査を依頼する
5. 会話、変更差分、テスト結果を確認する
6. 必要に応じて修正を依頼する
7. Pull Requestを作成して変更を取り込む

workspaceにはタスクごとのworktreeとブランチが割り当てられるため、別のタスクも並行して進められる。

## Orcaとの共通点

私は現在、複数のAIコーディングエージェントを管理する環境として[Orca](https://www.onorca.dev/)を使用している。

HelmorとOrcaは、複数のエージェントに対応していることや、Git worktreeを使ってタスクごとの作業環境を分離することなど、共通する部分が多い。どちらも、AIエージェント単体ではなく、複数の作業をどのように管理し、確認して取り込むかを支援するツールといえる。

| 項目 | Helmor | Orca |
| --- | --- | --- |
| 作業の分離 | タスクごとにGit worktreeとブランチを作成 | タスクごとにGit worktreeとブランチを作成 |
| 対応エージェント | Claude Code、Codex、Cursor、OpenCode、Kimi Codeなど | Claude Code、Codex、Cursor CLI、Gemini、OpenCodeなど |
| レビュー | 差分、エディタ、ターミナルを表示 | Diff Viewerから差分を確認してフィードバックできる |
| Git連携 | GitHubとGitLabに対応 | GitHubを利用したPull Request作成に対応 |
| 外部操作 | CLIとMCPサーバーを提供 | デスクトップとモバイルから操作できる |

機能一覧を見る限り、HelmorはPull Requestの作成やマージ、CI修正など、変更をリポジトリへ取り込むまでの流れを強く意識しているように見える。一方、OrcaにはWebアプリを確認するブラウザやDesign Modeがあり、画面を見ながらエージェントへ修正を依頼できる。

ただし、この比較は公開されている情報をもとにしたもの。実際の操作性や安定性、細かな機能差は、両方を使わなければ判断できない。

## 気になっている点

Helmorはまだ使用していないため、Orcaとの詳しい使い勝手の違いまでは分からない。

特に気になっているのは、エージェントの起動から差分レビュー、Pull Request作成までの操作性と、複数のタスクを並行して動かしたときの見やすさ。今後実際に試す機会があれば、普段使っているOrcaと比較してみたい。

比較するときは、次の点を確認したい。

- workspaceを作成してエージェントを起動するまでの手軽さ
- 実行中の複数タスクを把握しやすいか
- 変更差分への修正依頼を行いやすいか
- テストやCIで失敗したときに修正を続けやすいか
- Pull Requestを作成してマージするまでが分かりやすいか
- worktreeや終了したタスクを整理しやすいか

Orcaからすぐに乗り換えるというより、まずは同じ規模のタスクをHelmorでも試し、作業開始からPull Request作成までの違いを比較するのがよさそうだ。

## まとめ

Helmorは、複数のAIコーディングエージェントを独立したGit worktreeで動かし、実装、レビュー、テスト、Pull Request作成までをまとめて管理する開発環境。

現在使用しているOrcaと考え方はよく似ているが、HelmorはCLIやMCPからの操作、GitHubとGitLabへの対応、マージまで含めたワークフローに特徴がありそうだ。

まだ実際には使用していないため、現時点では機能の紹介にとどまる。今後試すことがあれば、Orcaと同じタスクを実行し、操作性やレビューのしやすさを比較してみたい。
