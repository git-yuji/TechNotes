# コードを書く機会が減った今の、ZedとVS Codeの使い分け

## 概要

最近は、自分でコードを書く機会が減ってきた。

普段の作業ではZedを使い、コードを読んだり、変更差分を確認したり、ターミナルでコマンドを実行したりしている。自分でコードを微修正するときだけ、VS Codeを使っている。

以前、[ZedでWeb制作をするときによく使う機能と操作](/notes/zed-web-development-workflow)をまとめた。今回は操作方法ではなく、現在の作業でZedとVS Codeをどのように使い分けているかを記録する。

## コードを書く機会が減った

エディタを使う作業には、コードを書くこと以外にも、ファイルを探す、処理を読む、変更内容を確認するといったものがある。

自分でコードを書く機会が減った今も、プロジェクトを開いて内容を確認するためにエディタを使っている。コードを入力する時間が減ったことで、読むことや確認することが、普段の作業の中で大きな割合を占めるようになった。

そのため、現在のエディタの使い分けも、コードを書く場面と、それ以外の作業をする場面で分かれている。

## 普段の作業はZed

基本的にはZedでプロジェクトを開いている。

主な用途は次の3つだ。

- コードを読む
- 変更差分を確認する
- ターミナルでコマンドを実行する

### コードを読む

プロジェクトの構成や処理の流れを確認するときは、Zedでファイルを開く。

必要なファイルを探し、関連するコードを読みながら、どこで何をしているかを確認する。自分でコードを書かない場面でも、内容を把握するためにエディタを使っている。

### 変更差分を確認する

変更が入ったときは、差分を見て、どのファイルのどの部分が変わったかを確認する。

ファイル全体を読むことと、変更された箇所を読むことでは、確認する目的が違う。差分では、追加・修正・削除された内容を見ながら、意図した変更になっているかを確認する。

### ターミナルで作業する

コマンドを実行するときも、Zedのターミナルを使っている。

コードや差分を確認する作業と、ターミナルでの作業を、普段使っているエディタの中で行っている。

## 自分で微修正するときはVS Code

VS Codeを使うのは、自分でコードを微修正するときだけだ。

普段はZedで内容を確認し、手動で少し直す必要があるときにVS Codeを開く。現在は、このように作業内容に応じてエディタを使い分けている。

Zedにもコードを編集する機能はある。ここで書いているのは、それぞれのエディタでできることの比較ではなく、自分が実際にどちらを使っているかという話だ。

コードを読むときはZed、手を動かして微修正するときはVS Code、という使い方になっている。

## 現在の使い分け

現在の用途を整理すると、次のようになる。

| 作業 | 使用するエディタ |
| --- | --- |
| コードを読む | Zed |
| 変更差分を確認する | Zed |
| ターミナルでコマンドを実行する | Zed |
| 自分でコードを微修正する | VS Code |

エディタを一つにまとめることよりも、今の作業に合わせて使うことを重視している。

自分でコードを書く機会が減っても、コードの内容や変更差分を確認する作業は残る。現在は、その確認をZedで行い、手動での微修正が必要なときにVS Codeを使っている。

## まとめ

普段の作業ではZedを使い、自分でコードを微修正するときだけVS Codeを使っている。

コードを書く機会が減ったことで、エディタを使う目的も、コードの入力だけでなく、読むことや変更内容の確認に比重が移ってきた。

今後、作業の進め方が変われば、エディタの使い方も変わるかもしれない。まずは、現在の使い分けを備忘録として残しておく。
