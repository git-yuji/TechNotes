# Herdr UIとは？AIエージェントの作業とレビューをGUIで管理するアプリ

## 概要

以前、[ターミナル版のHerdrについて調べた](/notes/herdr-agent-runtime-overview)。今回は、Herdrの作業をデスクトップ画面から管理できる[Herdr UI](https://herdrui.dev/)が気になったので、公開情報をもとに特徴を整理する。

Herdr UIは、複数のAIコーディングエージェントや作業環境をまとめて操作するデスクトップアプリ。macOS・Linux・Windowsに対応し、RustとGPUIで実装されている。

別途インストールしたHerdrのバックグラウンド処理に接続し、ターミナルの内容や分割ペインをGUIで表示する。Herdr UI自体がAIモデルを提供するわけではなく、普段使っているエージェントの実行状況や変更内容を確認するための操作・管理画面という位置づけになる。

なお、Herdr UIはHerdr公式とは独立したプロジェクトで、Apache-2.0ライセンスのオープンソースとして公開されている。この記事は機能紹介であり、実際に導入して使ったレビューではない。

## Herdr TUI・Herdr UI・新しい公式アプリの違い

似た名前のアプリがあるため、導入前に接続先を区別しておきたい。

| 名前 | 役割・位置づけ |
| --- | --- |
| 従来のHerdr TUI | ターミナル内からHerdrのセッションを操作する画面 |
| Herdr UI（penso/herdr-gpui） | 従来のHerdrのデーモンに接続する、独立プロジェクトのデスクトップクライアント |
| 新しいHerdr公式アプリ（herdrdev/herdr-app） | Herdr公式が提供する別のデスクトップアプリ。herdr-coreを使う |

Herdr UIと従来のHerdr TUIは同じセッションを表示するため、併用できる。ターミナルで進めている作業をGUIから確認する、といった使い方が可能になる。

一方、Herdr公式サイトで案内されている新しい公式アプリと従来のHerdr TUIは、セッションを共有しない。今回紹介するHerdr UIは、この新しい公式アプリとは別のものなので、インストールするアプリ名だけでなく、リポジトリや接続先も確認する必要がある。

## 主な特徴

### 作業環境とエージェントの状態をまとめて確認できる

サイドバーには、プロジェクトや関連するGit worktree、エージェントが表示される。

エージェントの状態も確認できるため、複数のターミナルを順番に開いて状況を調べなくても、作業中なのか、入力や確認を待っているのかを把握しやすい。

実際のターミナルやセッションの状態はHerdrのデーモンが管理する。GUIを閉じてもデーモンとターミナルは動き続けるが、マシンやデーモンの停止まで作業が継続するという意味ではない。

### 変更差分にコメントしてエージェントへ返せる

「Review Changes」から変更差分を開き、行ごとにレビューコメントを付けられる。差分は左右に並べる表示にも対応している。

確認した内容は「Send to agent」でエージェントへ送信できる。コードを生成させた後に、変更を読み、気になる箇所を指定して修正を依頼する流れをGUIで進められる点が特徴。

### ブラウザー上の要素に注釈を付けられる

ブラウザータブでは、ページの要素や範囲を選び、注釈を付けて担当エージェントへ送信できる。

たとえばNext.jsの画面を修正しているときに、余白やボタンの位置など、変更してほしい場所を示して指示を出す用途が考えられる。

ブラウザーはHerdr UI独自の機能であり、Herdr TUIとすべての表示が共有されるわけではない。ターミナルのセッション共有と、GUIだけが持つブラウザーや設定は分けて考えると分かりやすい。

### SSH接続先もまとめて管理できる

ローカルだけでなく、保存したSSH接続先の作業も扱える。

ローカルで進めるタスクと別マシンで進めるタスクを一つの画面で確認したい場合に役立ちそうだ。リモート側でエージェントを動かすためのHerdrや実行環境、認証などは、接続先でも準備する必要がある。

### Teleportで別ホストへ作業を引き継げる

Teleportは、リンクされたworktreeの作業を別ホストへ移す機能。ブランチやコミット、未コミットの変更、タブと分割構成、対応エージェントのセッションなどを引き継げる。

ただし、実行中プロセスのメモリー状態をそのまま移す機能ではない。コマンドは移動先で起動し直され、エージェントの会話は対応するセッション形式から再開される。

公開ドキュメントでは、次の制約も説明されている。

- TeleportはLinux・macOSのクライアントで提供される
- `.env`やビルド成果物などのGitで無視されたファイル、サブモジュールの内容は引き継がれない
- 環境変数、シェル履歴、バックグラウンドジョブ、未保存の編集内容は引き継がれない
- エージェントによってセッションの移行方法や対応状況が異なる

すべての開発環境がそのまま移ると考えず、移動先の依存関係や認証を確認し、移行前の確認画面で対象を確かめたい。

## 導入の流れ

まず、Herdr UIが接続する従来のHerdrデーモンを別途インストールする。Herdr UIには、Herdr本体をインストール・更新する機能はない。

Herdr UIはインストール済みのローカル`herdr server`を必要に応じて起動できるが、本体の導入を代わりに行うわけではない点に注意する。

Herdr UIの公開READMEに記載されている、macOSでの導入例は次のとおり。

```sh
brew install penso/tap/herdr-gpui
open -a Herdr
```

macOS版は14.2以降のApple Silicon・Intelに対応する。Linux版はglibcやVulkanドライバーなどの要件があり、Windows版には専用のインストーラーが用意されている。利用するOSに応じて、[READMEのインストール手順](https://github.com/penso/herdr-gpui#install)と[Releases](https://github.com/penso/herdr-gpui/releases)を確認する。

導入後は、おおむね次の流れで試せそうだ。

1. Herdrの接続先と作業用のリポジトリを確認する
2. worktreeを用意し、利用するエージェントを起動する
3. エージェントへ実装や調査を依頼する
4. サイドバーで進捗を確認し、変更差分をレビューする
5. 必要に応じてブラウザー上で表示を確認し、追加の指示を送る
6. テスト結果とGitの差分を確認して変更を取り込む

## 普段の開発で試したいこと

私は普段、複数のAIコーディングエージェントを管理する環境としてOrcaを使っている。

Herdr UIで特に気になるのは、ターミナル版Herdrと同じ作業を見ながら、差分レビューとブラウザー上の修正指示も行える点。以前調べたHerdrのターミナル中心の使い方に、画面を見て確認する工程を加えられそうだ。

このNext.jsのサイトで試すなら、一つのworktreeで画面を修正し、別のworktreeで別機能を進めながら、変更差分とプレビューを確認する使い方を考えている。

まずは小さな画面修正で、エージェントの起動から差分レビュー、追加指示までを一通り試したい。Orcaと比べた操作感や安定性、Teleportの実用性については、実際に使ってから判断したい。
