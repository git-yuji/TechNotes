# Rexとは？AIと複数端末での開発作業を支えるターミナル環境

## 概要

[Superlogical](https://www.superlogical.com/)は、ターミナルと開発作業の管理ツール「Rex」を開発している会社。AIを使った開発や、複数端末での作業を続けやすくすることを目指している。

Rexは、ターミナルに作業の継続、画面分割、リモート接続、AIからの操作を組み合わせた開発環境と考えると分かりやすい。

普段使っているCodexやClaude Codeにコードを書かせるだけでなく、別の画面でテストを実行したり、開発サーバーの出力を確認したりする操作まで任せられる点が気になった。

この記事では、2026年10月30日時点の公開情報をもとに、Rexの仕組みと利用時に確認したい点を整理する。実際に導入して使ったレビューではない。

## セッションで作業を継続する

Rexの中心にあるのは「セッション」という仕組み。

案件ごとのターミナルや実行中の処理をまとめ、タブや分割画面で整理できる。処理を維持するサーバーと、画面を表示して操作するクライアントが分かれており、アプリを閉じた後もサーバー側で維持された作業に再接続できる。

別の端末から作業の続きを操作することも想定されている。たとえば、開発サーバーやログ確認を含むセッションを用意し、接続する端末を変えても同じ作業に戻る使い方が考えられる。

ただし、クライアントを閉じても作業が続くことと、サーバーの停止やマシンの再起動後も同じプロセスが動き続けることは別。作業を維持するサーバーがどこで動いているかを把握しておきたい。

## 主な機能

| 機能 | できること |
| --- | --- |
| 作業の整理 | セッション・タブ・分割画面で開発作業をまとめる |
| 作業への再接続 | サーバー側で維持されたセッションへ接続し直す |
| コマンドからの操作 | セッションの作成や画面分割などをCLIから操作する |
| 自動化 | LuaやサーバーAPIで作業環境を制御する |
| AIとの連携 | AIがターミナルの内容を読み、別の画面でコマンドを実行する |

CLIやAPIが用意されているため、人が画面から操作するだけでなく、プログラムから開発環境を動かせる点が特徴になる。

毎回手作業で開いているターミナルや分割画面を準備したり、別のペインに処理を依頼したりする流れを、自動化できるか試してみたい。

## CodexやClaude Codeと組み合わせる

[エージェント連携のドキュメント](https://www.superlogical.com/rex/docs/automate/agent-skill)では、Claude Code・Codex・OpenCode・Pi向けの連携設定が案内されている。

Rex自体がコード生成を担当するのではなく、エージェントが開発作業を進めるための操作環境を提供する。エージェントはターミナルの内容を読み取り、必要に応じて別のタブや分割画面を操作する。

たとえば、次のような依頼が考えられる。

- 別のタブで開発サーバーを起動し、起動できたことを確認する
- 横の分割画面でテストを実行し、失敗した箇所を調べる
- ログ確認用の画面からエラーを読み取り、修正の手掛かりを探す

これらは公開されている機能から考えた活用例で、実機で検証した手順ではない。実際にどこまで操作できるかは、利用するエージェントの設定や権限も含めて確認したい。

また、セッションは作業をまとめる単位として捉え、コード変更を分離したい場合はGitのブランチやworktreeも用意する。画面を分けることと、変更するファイルを分けることは区別しておきたい。

## 現在の提供状況

2026年10月30日時点では、招待制のベータ版として案内されている。

| 対象 | 提供状況 |
| --- | --- |
| macOS | ベータテスター向けにクライアントアプリを提供。ローカルサーバーを内蔵 |
| Linux・FreeBSD | 一部テスター向けにサーバー版をアルファ提供 |
| Windows・iOSなど | 開発中。現行のインストール案内ではテスト対象外 |
| 入手方法 | メーリングリストに登録し、招待を待つ |

OSによって、操作画面を持つクライアントと、処理を維持するサーバーの提供状況が異なる。Linux向けサーバーがあることだけで、Linux用のクライアントも一般提供されているとは判断できない。

提供対象は変わる可能性があるため、導入前に[インストール案内](https://www.superlogical.com/rex/docs/installation)を確認する。

## 料金方針とプライバシー

[公開テスト開始の案内](https://www.superlogical.com/updates/public-testing-beginning)では、Rexのクライアントとサーバーは今後も無料、利用アカウント不要、セルフホスト可能という方針が示されている。一方、Superlogical全体の収益化方法は未発表。

Rexの利用にアカウントが不要という方針と、ベータ版を入手するための手続きは別で、現時点のダウンロード案内ではDiscordログインが必要とされている。

また、[プライバシーの説明](https://www.superlogical.com/rex/docs/reference/privacy)では、Rex自体は利用状況の分析データを収集しないとしている。ただし、Mac版の更新確認などの通信はあり、外部との通信が一切ないという意味ではない。

Rexの中で動かすCodexやClaude Codeなどの通信やデータの取り扱いは、それぞれのサービスに依存する。Rexの方針だけで、AIツールへ送信される情報まで判断しないようにしたい。

## 開発チームについて

Superlogicalには、Ghosttyの作者でHashiCorp共同創業者でもあるMitchell Hashimoto氏が参加している。ほかにも、HashiCorp・Vercel・Herokuなどで開発やデザインを担当してきたメンバーが紹介されている。

開発者向けツールに関わってきたメンバーが、AIや複数端末での作業に合わせてターミナルをどう設計するのかが気になる。ただし、チームの経歴と自分の開発に合うかどうかは別なので、操作感は実際に試して確認したい。

## 普段の開発で試したいこと

このNext.jsのサイトで使うなら、案件用のセッションに次の画面をまとめる構成を試してみたい。

| 画面 | 用途 |
| --- | --- |
| 開発サーバー | ページの表示確認と起動ログの確認 |
| CodexやClaude Code | 実装や調査の依頼 |
| Git操作 | 変更差分とブランチの確認 |
| テスト・ログ | 検証結果やエラーの確認 |

AIに実装を依頼した後、別の分割画面でテストを実行し、失敗した出力を読み取って修正する流れを、どこまで自然に進められるかが気になる。

以前調べた[Herdr](/notes/herdr-agent-runtime-overview)にも、ターミナルを保持して複数の作業を管理する考え方がある。Rexでは、セッションへの再接続とCLI・APIによる制御、エージェント連携が日常の作業でどうつながるかを見てみたい。

まずは個人の小さなプロジェクトで、セッションの作成、アプリを閉じた後の再接続、AIからのタブや分割画面の操作を試す。まだテスト段階のため、普段の作業に合うかを確かめてから導入を判断したい。
