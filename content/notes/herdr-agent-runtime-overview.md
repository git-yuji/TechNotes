# Herdrとは？普段使っているOrcaとの違いを調べてみた

## 概要

私は普段、複数のAIコーディングエージェントを管理するために[Orca](https://www.onorca.dev/)を使っている。

Orcaと似た用途に見えるツールとしてHerdrを知り、何ができるのか、どこが違うのかを調べてみた。

[Herdr](https://herdr.dev/)は、Claude Code、Codex、OpenCodeなどのCLI型AIコーディングエージェントを、複数のターミナルペインで実行・管理するためのオープンソースのターミナルランタイム。

Herdr自体がAIモデルを提供するのではなく、普段使っているCLIエージェントを実際のターミナルプロセスとして動かし、状態確認や別マシンからの操作を支援する。

## Herdrの仕組み

Herdrは、バックグラウンドで動くサーバーと、そこへ接続するクライアントに分かれている。

サーバーがターミナルとプロセスを保持するため、画面を閉じてもエージェントや開発サーバーは動き続ける。画面は次の単位で整理される。

| 単位 | 役割 |
| --- | --- |
| Workspace | リポジトリやタスクをまとめる単位 |
| Tab | エージェント、ログ、サーバーなどの表示を分ける単位 |
| Pane | シェルやエージェントが動く実際のターミナル |
| Agent | Pane内でHerdrが認識したAIコーディングエージェント |

既存のターミナル内で動くTUIで、tmuxに似たキーボード操作に加え、ペインの選択や分割、サイズ変更をマウスでも行える。

## 主な特徴

### エージェントの状態を一覧で確認できる

Herdrは各ペインのエージェントを検出し、`working`、`blocked`、`done`、`idle`などの状態をサイドバーへ表示する。すべてのペインを順番に開かなくても、入力や承認を待っているエージェントを見つけられる。

Claude Code、Codex、Cursor Agent CLI、OpenCode、GitHub Copilot CLIなどが自動検出の対象。未対応のCLIも通常のターミナルプロセスとして実行できるが、状態表示は制限される場合がある。

### CLIやSocket APIから操作できる

CLIやローカルのSocket APIを使い、Paneの作成、エージェントの起動、プロンプトの送信、出力の読み取り、状態の待機などを自動化できる。

一つのエージェントが別のペインにレビュー用のエージェントを起動し、完了後に結果を読み取るような連携も可能になる。

### SSH先のエージェントも管理できる

SSH接続できるマシンを登録すると、ローカルとリモートのWorkspaceやエージェントを一つの画面から切り替えられる。

各マシンでは別々のHerdrサーバーが動くため、一台との接続が切れても、ほかのマシンの接続や実行プロセスには影響しない。

## Orcaとの比較

Orcaも複数のCLI型AIコーディングエージェントを管理するツールだが、中心となる役割が異なる。

| 比較項目 | Herdr | Orca |
| --- | --- | --- |
| 位置付け | エージェントが動くターミナルランタイム | エージェントとの開発全体を扱うADE |
| 主な画面 | 既存のターミナル内で動くTUI | エディタやブラウザを備えたデスクトップアプリ |
| 作業の整理 | Workspace、Tab、Pane | プロジェクト、タスク、Git worktree |
| 作業の分離 | 自動では分離しない | タスクごとにworktreeとブランチを作成する |
| レビュー | ターミナル出力を読み取る | Diff Viewerで変更差分を確認できる |
| Webアプリの確認 | 専用ブラウザは持たない | ブラウザとDesign Modeを利用できる |
| 向いている用途 | ターミナル中心の作業やエージェント同士の自動連携 | 実装から表示確認、差分レビューまでを一つの画面で行う作業 |

### Orcaを使っている立場から見たHerdr

公式情報を比較した限り、HerdrはOrcaをそのまま置き換えるツールではないと感じた。

OrcaはタスクごとにGit worktreeを作り、変更差分やブラウザの表示まで一つの画面で確認できる。Herdrには同じレビュー環境がないため、乗り換えると作業の分離や差分確認を別のツールで補う必要がある。

一方、Herdrは既存のターミナルを使えること、SSH先もまとめて扱えること、CLIやAPIからエージェント同士を連携できることが気になった。GUIでのレビューを必要としない調査や長時間の処理では、Orcaより合う場面もありそうだ。

Herdrは「エージェントが動く場所」、Orcaは「エージェントと開発を進める場所」と考えると違いが分かりやすい。まだHerdrを実際に使った評価ではないため、操作感や状態検出の精度は試して確認したい。

## 利用時の注意点

Herdrはエージェントの実行状態を管理するツールであり、AIによるファイル変更の正しさや安全性を保証するものではない。

複数のエージェントに同じリポジトリを変更させる場合は、Git worktreeやブランチで作業場所を分離し、変更差分とテスト結果を人が確認する必要がある。

## まとめ

Herdrは、CLI型AIコーディングエージェントが動くターミナルを保持し、複数の作業を一つのTUIから管理するランタイム。

普段Orcaを使っている自分にとって、完全な乗り換え先というより、ターミナル中心の作業や複数マシンでのエージェント実行に向いた選択肢に見える。

Orcaでタスクの分離とレビューを行いながら、Herdrが得意とするCLIからの自動化やSSH先の管理を試し、使い分けられるか確認したい。
